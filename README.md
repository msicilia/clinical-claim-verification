# Verification of clinical claims grounded in standardized medical vocabularies

Code for the benchmark and experiments of the paper *Verification of Clinical Claims
Grounded in Standardized Medical Vocabularies*. A clinical claim is normalized
through the OMOP CDM standard vocabularies, evidence is retrieved from FDA drug
labels, and each facet of the claim is verified separately: entailment for the
drug–condition relation, a numeric comparison for the dose.

The repository contains code only. All data are public and are downloaded or
generated by the scripts, as described below. Ground truth is assigned when the
benchmark is generated, so no manual annotation is needed.

## Install

The project uses [uv](https://docs.astral.sh/uv/). `uv.lock` pins the exact versions
used for the paper.

```bash
uv sync
```

Run every script from the repository root with `uv run python <script>`; paths are
relative to the root, and all data go under `data/`. The first model run downloads
the model weights (about 1 GB). The commands below omit the `uv run` prefix.

## Data

**FDA drug labels** (needed by the benchmark and all C2 experiments):

```bash
mkdir -p data
python fetch_labels.py 1000          # -> data/labels_raw.json
python build_benchmark_ner.py        # -> data/benchmark_ner.jsonl
```

`fetch_labels.py` downloads the labels openFDA returns at the time it is run. openFDA
is updated continuously, so a new download yields a different set of labels, and
figures will differ slightly from those reported in the paper.

**OMOP vocabularies** (needed by the C1 scripts and `cadec_*`). Download the Athena
vocabulary bundle (SNOMED and RxNorm) from <https://athena.ohdsi.org>, unzip it into
`data/omop/`, then keep the standard Condition concepts and their synonyms:

```bash
cd data/omop
awk -F'\t' 'NR>1 && $3=="Condition" && $6=="S" {print $1"\t"$2}' \
    CONCEPT.csv > concept_cond.tsv
awk -F'\t' 'NR==FNR{a[$1];next} FNR>1 && ($1 in a){print $1"\t"$2}' \
    concept_cond.tsv CONCEPT_SYNONYM.csv > synonym_cond.tsv
cd ../..
```

**PubMed abstracts** (C1) are downloaded by `condition_experiment.py` on first run
and cached in `data/abstracts.json`.

**SciFact**: download <https://scifact.s3-us-west-2.amazonaws.com/release/latest/data.tar.gz>
and unpack it so that the files are under `data/data/`
(`tar -xzf data.tar.gz -C data`). **CADEC** and **MedHallu** are downloaded
automatically through the `datasets` library.

**Local language model** (needed by `llm_omop_c1.py`, `cadec_linker.py` and
`llm_verifier_baseline.py`): [Ollama](https://ollama.com) running locally
(`ollama serve`) with `medgemma:4b`, and `qwen3:32b` for the larger-model probe.
Answers are requested at temperature 0 and cached under `data/`.

## Scripts

`[bench]` defaults to `data/benchmark_ner.jsonl`; arguments in brackets are optional.

### Benchmark

| Script | |
|---|---|
| `fetch_labels.py [N]` | download N prescription drug labels from openFDA |
| `build_benchmark.py` | generate claims, with condition extraction by regular expression |
| `build_benchmark_ner.py` | generate claims, with condition extraction by biomedical NER (used by the experiments) |

Each label yields one true claim and up to three false claims (wrong drug, unsafe
dose, wrong indication). A false claim is dropped if some label in the corpus
asserts it.

### C1: OMOP normalization and retrieval (Section 4.1, Table 2)

All C1 scripts use the same TF-IDF retriever and PubMed corpus.

| Script | |
|---|---|
| `omop_experiment.py` | brand-to-generic queries against drug labels |
| `condition_experiment.py` | lay queries against PubMed abstracts: raw, naive string cleanup, oracle |
| `omop_link.py` | the deterministic OMOP linker, `concept(s)` and `syn(c)` of Equation 1 (imported, not run) |
| `omop_c1_real.py` | exact OMOP lookup |
| `embed_omop_conditions.py` | run once: embed the OMOP condition names for the fallback |
| `omop_c1_full.py` | exact lookup with an embedding fallback |
| `llm_omop_c1.py` | LLM-assisted linker: the model proposes a clinical term, OMOP links it |

### C2: verification strategies (Sections 4.2–4.3, Table 3)

| Script | |
|---|---|
| `retrieve_verify.py [bench]` | lexical nearest-neighbour baseline |
| `nli_gate_experiment.py [bench]` | whole-label NLI gate |
| `nli_gate_sentence.py [bench]` | sentence-level NLI gate |
| `nli_gate_decomposed.py [bench]` | decomposed gate, the final pipeline |
| `nli_gate_decomposed_mednli.py [bench]` | decomposed gate with a biomedical NLI model |
| `nli_gate_decomposed_biomed.py [bench]` | decomposed gate with a biomedical retriever |
| `llm_verifier_baseline.py --model M` | a language model makes the verdict instead of the gate |

The gate scripts print a sweep over the entailment threshold; the paper reports 0.5.
`llm_verifier_baseline.py` imports the corpus and retrieval settings from
`nli_gate_decomposed.py` and gives the model the opening 1,200 characters of each
retrieved label; see its docstring for the options used in the paper.

### External validation (Section 4.4, Table 4)

| Script | |
|---|---|
| `scifact_gate.py`, `scifact_gate_mednli.py` | the gate on SciFact claims (general and biomedical NLI) |
| `cadec_linker.py [N]` | the LLM-assisted OMOP linker on CADEC patient lay spans |
| `cadec_extraction.py [N]` | entity extraction from raw CADEC forum sentences |
| `medhallu_experiment.py` | the gate on MedHallu, whole-answer entailment |
| `medhallu_experiment_v2.py [N]` | MedHallu with answer decomposition and a contradiction signal |
| `medhallu_experiment_mednli.py [N]` | as above, with the biomedical NLI model |

## Main results

```bash
# prefix each command with `uv run`
python fetch_labels.py 1000
python build_benchmark_ner.py
python condition_experiment.py; python omop_c1_real.py; python llm_omop_c1.py    # C1
python nli_gate_decomposed.py                                                     # C2, final gate
python llm_verifier_baseline.py --model medgemma:4b                               # C2, LLM verifier
```
